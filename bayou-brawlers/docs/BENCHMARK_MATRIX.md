## Evidence and comparison limits

No predecessor game build or recording was supplied. The new slice now has local browser evidence and independent criticism, but this session still has no direct instrumented capture from the three reference games. Consequently:

- “Current behavior” distinguishes source-observed intent from behavior that still requires live proof.
- “Reference behavior” is a qualitative comparison hypothesis to verify through direct play or legally available recorded material. It is not a claimed measurement.
- Exact reference startup, recovery, buffer, hitstop, frame-pacing, load, or restart values are unknown and are not invented here.
- The first testing pass must add build ID, browser, device, hardware, capture rate, scenario, repetitions, observed result, and evidence link.
- Visual-style differences are not failures. The comparison concerns timing, clarity, responsiveness, flow, coherence, and intent.

## First comparison order

1. Establish Bayou Brawlers’ own live baseline before making reference claims.
2. Capture legally available, role-comparable reference sequences or run direct instrumented play where available; document which method was used.
3. Compare input and movement first, then combat contact, flow/depth, enemy pressure, encounter composition, boss readability, presentation, and complete-slice integration.
4. Use blind clips where practical and ask which sequence is more responsive, clearer on hit, easier to read in crowds, better paced, easier to understand, and more polished—and which single difference decided the preference.
5. Advance no status based on code completion alone. Runtime evidence, regression checks, and a fresh critic verdict are required.
